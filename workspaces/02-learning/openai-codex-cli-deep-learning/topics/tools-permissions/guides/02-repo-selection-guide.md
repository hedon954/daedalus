# 02 Repo 选择指南

## 首选候选

### `openai/codex`

- 为什么匹配：用户明确希望学习 Codex CLI 源码；该仓库最直接覆盖真实 Agent CLI 的命令入口、会话控制、工具执行、权限和沙箱边界。
- 核心能力：Agent loop、上下文组织、工具调用协议、命令执行安全边界、交互式 CLI/TUI 工程组织。
- 适合阅读的入口：先从 CLI 启动入口和命令分发开始，再追踪一次用户 prompt 的执行路径。
- 可能的 mini demo：最小 Agent CLI，包含会话状态、上下文裁剪、工具注册、权限检查、命令执行模拟和结果回传。
- 风险：仓库可能快速变化；运行可能依赖登录、网络、模型服务或平台能力；部分路径需要用测试或 mock 代替真实调用。

## 暂不选择的替代方向

- 其他 Agent 框架：可能更适合学习通用 Agent 编排，但不能直接回答“Codex CLI 源码如何工作”。
- 只读文档或教程：上手快，但无法支持核心代码精读和 mini demo 迁移。

## 建议结论

优先选择 `openai/codex`。理由是它与用户目标完全对齐，且具备足够真实的工程约束；学习风险主要来自运行环境和外部服务依赖，应通过固定源码版本、记录 runbook、优先使用本地测试和 mock 来控制。

## 需要用户确认

- 接受上述运行风险后，才能把选择结论写入 `notes/01-repo-selection.md` 并完成本阶段。
- 源码拉取建议固定 commit，而不是直接跟随 `main`。
