# 记录使用 codex 来验证 stage 01-03 阶段的真实教学效果



可以改进的问题：

1. 当开始学习一个 repo 的时候，如果通过 git clone 把一个 repo 拉到 `source` 目录下时，需要写 .gitignore 来忽略源码，并删除拉下来的仓库自带的 `.git` 目录，避免提交给 git，导致当前知识库过大。但是可以提供一个 pull_source.sh 脚本用于拉取源码，这样用户在别的环境，也可以按需拉取所需的原材料。
2. 有一个问题就是，daedalus 一直自己在做，在更新状态，再持续往后面推进，但是这个过程，用户的参与有点少，导致学习延续性较差，应该尽可能跟用户进行交互，提高用户的学习积极主动性，所以学习步骤应该尽可能单元化、细粒度，这样才能持续指导用户一步步往下走。你需要明白，核心原则是：**你需要区分什么是该 daedalus 做的，什么是一定要用户去手动实践的。我们不要 daedalus 一直包揽包干，而是要它一直指导用户去实践，然后 daedalus 负责验收、排难和持续规划**。另外，daedalus 每次在执行的时候，应该说明自己在做什么，为什么要做，等待的过程中用户可以做什么（思考什么），然后做完了需要对用户进行引导。
3. debug-guide 应该是指导用户去启动项目，由用户自己来自动，而不是 daedalus 帮忙启动，这个过程核心是要让用户自己参与、自己学习、自己感受，而不是"表面上完成了某个任务"，所以不应该由 daedalus Agent 来做。后续所有学习指导的过程中，也需要秉持这个原则。
4. 由 daedalus 在指导过程中生成的建议，应该放在对应学习任务目录的 `guides` 目录下，`notes` 目录应该是用户自己创建的手写笔记。（所以相关的 templates 也需要补充 `guides` 这个目录，涉及到的说明文档也需要进行补充）
